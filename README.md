# reDTF Share Service

Минималистичный сервис предпросмотра (Open Graph) для [reDTF](https://github.com/re-dtf/client).

Позволяет мессенджерам и соцсетям (Telegram, Discord, Twitter/X, VK, WhatsApp и др.) отображать полноценные превью постов с DTF (название, обложка, цитата статьи) без нарушения принципа прозрачности основного сайта `redtf.org`.

---

## Зачем это нужно?

* **`redtf.org`** остаётся 100% статичным клиентом на GitHub Pages без проксирования и закрытых серверов (Zero Server Logic).
* Боты мессенджеров (например, `TelegramBot`) не исполняют клиентский JavaScript, поэтому чистый SPA на GitHub Pages отдаёт им лишь стандартный пустой шаблон.
* Данный сервис выступает лёгким шлюзом:
  1. **Краулеры и боты** получают легковесный HTML со сгенерированными тегами `og:title`, `og:image`, `og:description` и `twitter:card`. Метаданные запрашиваются из публичного API DTF (`api.dtf.ru`) без авторизации.
  2. **Реальные пользователи** при клике мгновенно перенаправляются (HTTP 302) на целевой веб-клиент (по умолчанию `https://redtf.org/post/<id>`).

Никаких секретов, паролей или токенов через сервис не проходит.

---

## Как это работает

| Запрос | Человек | Бот |
| :--- | :--- | :--- |
| `/post/<id>` | 302 на `<TARGET_ORIGIN>/post/<id>` | HTML с превью поста |
| `/` | 302 на клиент | HTML с превью сайта |
| любой другой путь | 302 на клиент | 404 |
| не `GET`/`HEAD` | 405 | 405 |
| превышен лимит запросов к DTF | — | 429 |

* **Кто бот** определяется по `User-Agent`. Параметры `?preview=1` и `?og=1` принудительно включают режим бота, `?redirect=1` выключает. Эти служебные параметры на целевой сайт не передаются.
* **Что попадает в превью.** Заголовок — `ogTitle` или `title`. Описание — текст блока с флагом `cover` (то, что DTF показывает в ленте), затем любой открытый текстовый блок, затем `ogDescription`. Картинка — обложка поста или первая картинка из блоков.
* **Что не раскрывается.** Спойлеры (`hidden`) пропускаются. У поста с пометкой 18+ (`isBlur`) картинка заменяется на `DEFAULT_IMAGE`. Неопубликованный или скрытый по требованию пост (`isPublished: false`, непустой `withheld`) отдаётся с обычным превью сайта.
* **Если пост получить не удалось** (404, ошибка DTF, тайм-аут 4 с), боту отдаётся обычное превью сайта на 60 секунд, а не редирект: иначе бот пошёл бы на пустой SPA, и мессенджер надолго запомнил бы пустую карточку. Причина (кроме обычного 404) пишется в лог воркера.
* **Адреса в тегах.** `og:url` указывает на сам шлюз (`<домен шлюза>/post/<id>`), чтобы краулеры, которые перескрапывают `og:url` (например, Facebook), не ушли на SPA без тегов. `canonical` и ссылка «Открыть» ведут на `TARGET_ORIGIN`. Автоперехода (`meta refresh`) в HTML нет: Telegram идёт по нему на целевой сайт, а тот на GitHub Pages отвечает 404 для адресов SPA, и карточка не строится. Людей перенаправляет 302 ещё до этого.
* **Кэширование.** Ответы бота содержат `Cache-Control: public, max-age=<CACHE_TTL>` и `Vary: User-Agent`. На Cloudflare Workers готовый HTML дополнительно кэшируется в Cache API по адресу поста на шлюзе (параметры запроса кэш не обходят), поэтому DTF опрашивается не чаще одного раза за `CACHE_TTL`. Сбой тоже кэшируется, но на 60 секунд. Cache API работает только на собственном домене, на `*.workers.dev` кэша нет.
* **Защита DTF от спама.** Кэш не помогает против запросов с разными id: каждый такой промах уходит в API DTF. Поэтому поход в DTF ограничен общим лимитом (Rate Limiting binding `DTF_LIMITER` в `wrangler.toml`, по умолчанию 60 в минуту на дата-центр). Сверх лимита бот получает `429` с `Retry-After`, а ответ не кэшируется, чтобы мессенджер не запомнил пустую карточку. Номер поста — не больше 10 цифр. Без binding (свой деплой) лимита нет.

## Переменные окружения (для селфхоста)

Все параметры необязательны:

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `TARGET_ORIGIN` | `https://redtf.org` | Базовый URL вашего клиента reDTF, куда редиректить живых пользователей |
| `SITE_NAME` | `reDTF` | Название сайта в `og:site_name` |
| `DTF_API_URL` | `https://api.dtf.ru/v2.31` | Базовый адрес API DTF для получения данных постов |
| `CACHE_TTL` | `7200` | Время кэширования превью ботами и CDN (в секундах) |
| `DEFAULT_IMAGE` | `https://redtf.org/icons/app-default-512.png` | Изображение по умолчанию, если у поста нет обложки |
| `DEFAULT_TITLE` | `reDTF — неофициальный клиент DTF` | Заголовок по умолчанию для главной страницы |
| `DEFAULT_DESCRIPTION` | `Неофициальный легковесный клиент для DTF...` | Описание по умолчанию |

## Инструкция по развертыванию (Cloudflare Workers)

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/re-dtf/share.git && cd share
   npm ci
   ```
2. Измените `wrangler.toml` под себя: домен в `routes` (или удалите `routes` и привяжите домен в дашборде: **Workers & Pages** &rarr; ваш воркер &rarr; **Settings** &rarr; **Domains & Routes**) и, если у вас свой форк клиента, `TARGET_ORIGIN`:
   ```toml
   routes = [{ pattern = "s.your-domain.org", custom_domain = true }]

   [vars]
   TARGET_ORIGIN = "https://your-domain.org"
   ```
   Переменные из `wrangler.toml` при каждом деплое перезаписывают те, что заданы в дашборде Cloudflare.
3. Задеплойте:
   ```bash
   npm run deploy
   ```

Деплой из GitHub Actions включается секретами репозитория `CF_API_TOKEN` и `CF_ACCOUNT_ID`.

> Сервис открытый: любой может запросить превью любого поста. DTF защищён общим лимитом `DTF_LIMITER` (см. выше), но сам воркер от потока запросов он не бережёт. Если нагрузка станет проблемой, добавьте в Cloudflare правило ограничения запросов (Rate limiting) на ваш домен.

## Тестирование и отладка

Для локального запуска тестов нужен Node.js 22.18 или новее:
```bash
npm test
```

Чтобы проверить, как сервис видит пост, запросите страницу от имени бота:
```bash
curl -A "TelegramBot" https://s.redtf.org/post/5394366
```
Тот же HTML отдаёт и запрос с `?preview=1`, и обычный браузер покажет страницу со ссылкой «Открыть в reDTF». Теги удобно смотреть через `curl` или «Просмотр кода страницы».
